📌 1. Executive Summary & Problem Statement

In traditional commercial retail markets and residential complexes, managing monthly rent collections, electrical sub-meter utility readings, and municipal tax liabilities across dozens of units is overwhelmingly manual, opaque, and prone to severe revenue leakage. Property owners face persistent friction due to fraudulent online transaction claims, fabricated UPI payment screenshots, misplaced paper slips, and cumbersome dispute reconciliation.

The Solution: Naseeb Lal Market is an integrated commercial property management suite that pairs a native Android Admin Application (for property owners and field collectors) with a zero-barrier, mobile-first Web Portal (for retail tenants). Through real-time cloud synchronization, automated utility calculations, and an anti-fraud reconciliation queue, it establishes an airtight, paperless property workflow.

⚙️ 3. Core Functional Modules

  • Dual-Workspace Management: Seamless 1-tap switching between Public Commercial Market (retail shops) and Private Residential Flats, providing segregated analytics while maintaining single database consistency.
  • Role-Based Access Control (RBAC): Super-Admin maintains full administrative control over rent corrections, activity audits, and sub-admin accounts. Field Sub-Admins are limited strictly to recording payments and logging meter readings.
  • Utility Meter & Municipal Tax Billing Engine: Automates electricity sub-meter calculation using: Due = (Current Reading - Previous Reading) × Tariff Rate. Tracks Patna Municipal Corporation (PMC) holding tax clearances with automated reminder windows.
  • Anti-Fraud Payment Verification Pipeline (Tenant Echo): Eliminates fake payment claims. When a tenant enters an online UTR or cash note on the web portal, the form immediately locks to prevent duplicates. The claim is routed to the Admin dashboard's dedicated QUEUE badge. Only after manual bank reconciliation does the admin tap 'Verify & Mark Full Paid', which cryptographically provisions a tamper-evident receipt number and unlocks the official receipt on the tenant's browser.
  • Live State Watcher & Instant Receipt Unlock: The web portal features an active background polling observer (7s interval). When Admin verifies payment in the Android app, the tenant's web view automatically transforms into the official stamped PDF receipt with Print and WhatsApp share buttons without a manual page refresh.

💡 5. Senior-Level Technical Interview Q&A

Q1: Why did you choose Jetpack Compose over traditional XML Layouts?
Compose uses a declarative paradigm where UI is a pure function of state (UI = f(State)). In this application, real-time sync indicators, meter reading cards, and payment queue badges undergo frequent live state mutations. With Compose and StateFlow (observed via collectAsStateWithLifecycle), the framework performs intelligent recomposition on only the modified nodes. This eliminated complex View-binding boilerplate, reduced lines of code by over 40%, and completely eradicated null-pointer exceptions.
Q2: How did you achieve real-time synchronization between Android and the Web Portal?
We leveraged Firebase Realtime Database as the shared Single Source of Truth. The Android app maintains persistent WebSocket streams that emit snapshots into StateFlow pipelines. When a tenant submits a UTR on the web portal, an atomic REST PATCH updates the /rents/{id} node with tenantClaimedPaid: true. The Android dashboard immediately reflects this in the Queue filter. When approved, the status transitions to PAID. The web portal features an active polling observer that detects the change, transitions out of the pending state, and renders the official receipt.
Q3: Why a Web Portal for tenants instead of a Tenant Mobile App?
This was a deliberate UX and product strategy decision. Retail shopkeepers resist installing 50MB mobile applications and frequently forget credentials. By building a mobile-first Web Portal accessible via query parameters (?shop=5), we achieved zero barrier to entry. The tenant taps a monthly WhatsApp link, reviews their bill, enters their transaction reference, and saves their receipt. It maximizes compliance and adoption.
Q4: How did you prevent fraudulent payment submissions?
We enforced a two-stage verification barrier. A tenant submission is strictly categorized as an unverified claim (UNDER_REVIEW) and locks the input fields. The transaction appears in the Admin's dedicated 'Queue' badge. The property manager verifies the exact UTR against their live bank statement. Only when the manager clicks 'Verify & Mark Full Paid' does the system generate the official receipt number (NLM-YYYY-UNIT-XXXX) and unlock the sealed digital receipt on the tenant's device.
Q5: How does the system handle offline environments and network dropouts?
The Android app employs Firebase local disk persistence and SharedPreferences-backed data caching. If a field collector records a cash payment in a basement with zero connectivity, the local ledger updates immediately without freezing the UI. Once network connectivity is restored, Firebase's offline queue automatically synchronizes the transactions with cloud timestamps and activity audit logs.
